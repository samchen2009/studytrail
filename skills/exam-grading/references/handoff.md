# 评分与解析的交接约定

这是技能间的最小业务约定；现有 StudyTrail v1 接口尚未实现拆分，不能将下列字段直接发送给旧接口。代码迁移见 `docs/grading-pipeline-plan.md`。

## 一次采集，两阶段复用

| 内容 | 必须保留的信息 |
| --- | --- |
| 材料身份 | 本次考试、分析范围、源文件哈希、文件角色、稳定页 ID、原页号与尺寸；合成页/裁片到原图的变换 |
| 题目清单 | 稳定 questionId、原题号、题组、题型、小问关系、所有题干/选项与共用材料的引用；未完成识别也留清单状态 |
| 学生证据 | 最终作答转写、原图区域、涂改与不确定说明；题卷上手写内容不能替代答卷 |
| 答案依据 | 正式答案或独立推导、版本、必要验证与争议说明；能据此判分的简短结论 |
| 评分快照 | gradeSetId、源材料版本、评分模式与规则版本、逐题得分/满分、证据与理由、失分原因（未作答/无法识别/答案错误）、待核状态、原批分的独立记录 |
| 几何位置 | pageId、原图坐标的矩形或多段线、anchorText、位置置信度及人工修正；与答案/评分置信度分开 |
| 解析输入 | 固定 gradeSetId、上述材料引用、通用解析技能及所用学科技能的版本 |

具体字段名可以适配运行环境，以上语义不可丢。技能在聊天执行时可保存本地 JSON；应用实现应有独立 schema 和校验，不能只靠模型遵守提示。

## 必须一致的约束

- 跨页同题一个计分项，小问按清单归属；同号不同题组不能误合并。已阅页面不等于已覆盖全部题目。
- 得分点之和等于该题得分，各项满分之和等于该题满分；分类合计与逐题合计相等。原批合栏分不强拆成逐题分。
- 正式分与参考分不混加；等权参考分的全卷分母按参与评分的编号题数计算。待核题保留上限，不并入已确认得分。
- 依批改技能，完整材料中学生未作答或作答无法识别的评分点记0分，计入已评分合计，不作为待核上限；无法识别与答案错误分别记录，保留原图证据及实际识别置信度。低识别置信度本身不能把已按此规则判定的失分重新变成空分或待核范围。附件/题干/参考依据缺失与学生作答缺失分开处理。
- HTML 批改卷（按需 PDF） 与解答册（默认离线HTML，按需PDF）均绑定同一 gradeSetId。解析文字、裁片与图形可有独立版本，不能因修改排版或输出格式而重批。
- 解析仅消费评分快照，不覆盖它。发现冲突保存 `reviewIssues`；只有完成明确复核后才产生新评分版本并标识旧成果过期。
- 每阶段使用独立且稳定的任务 ID，恢复时查询原阶段任务，不重新提交已完成的评分。结果落盘后才宣告阶段完成；PDF 导出失败只重排版。
- 原卷、结果、独立题图、HTML、按需 PDF 和任务状态均存本地忽略目录；进入技能或方案的例子只能使用虚构数据。
