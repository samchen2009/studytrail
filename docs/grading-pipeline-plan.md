# 评分先出卷、解析后完成：优化方案

状态：默认交付已统一为 HTML 批改卷与 HTML 解答；逐题图像独立保存、一键收录及按需 PDF 已实现。下文两阶段 AI 任务、技能自动加载仍为规划；旧方案中的默认评分 PDF 已由本次 HTML 流程取代。

## 现有实现与瓶颈

| 位置 | 已有能力 | 需要改进 |
| --- | --- | --- |
| `web/grading-tandix.mjs` · `buildPrompt()` | 一次识别、评分、详细解法和知识总结；Tandix 持久任务恢复 | 最慢的详细解析拖延评分交付；大 JSON 最终返回前没有可保存的阶段成果 |
| `web/grading-core.js` · `validateResult()` | 评分点加总、题号、坐标、置信度等校验；后端复用 | 每题强制有 `methods`，不接受仅评分结果；已阅页检查不能独立发现漏题 |
| `web/grading.js` · `generatePdfs()` | 依次生成并保存 marked、answers | 虽先生成 marked，但前提仍是完整 AI 结果；缺少独立阶段进度与重试入口 |
| `web/grading-pdf.mjs` / `api/grading-html.js` | 评分PDF与离线解答HTML，公式预渲染、嵌入字体和原图 | 评分PDF仍为整页图片；解答后续补精确原题裁片及手写行级划线 |
| `api/grading.js` / `api/grading-runs.js` | 版本化本地存储、并发保护、原任务恢复 | 一份评分版本和一份 AI 执行记录不足以表达两个独立阶段；导出未区分评分、解析及标注版本 |

保留已有版本控制、人工校准、恢复和删除恢复能力，不重做一套附件系统。

## 建议流程

```text
上传题卷 / 答卷 / 可选答案
  → 本机一次预处理：页码、方向、文件哈希、题号清单与原图区域
  → 阶段 A：批改技能（正确答案核实＋作答证据＋简短给扣分理由）
  → 校验并冻结评分快照 → 立即生成 HTML 批改卷，可先查看
  → 阶段 B：通用解析技能＋学科细则（使用同一份材料和评分快照）
  → 解析检查与排版 → 离线解答HTML单独下载，按需打印PDF
```

批改仍需正确解题，不能用“快”省略答案核验；加速来自不等待长篇讲解、复用识别与定位，以及局部失败重试。评分 PDF 不再以长篇逐题成绩页开头：优先一页概要，随后原答卷上给勾叉、分数和必要短评。

### P0：先拆开等待链

1. 新增独立 grading、analysis 结果契约与校验；批改不要求教学 `methods`/`knowledgeSummary`，保留答案、证据、rubric 和位置。不能给旧校验器塞空解法冒充兼容。
   评分状态按最新技能区分：完整答卷中未找到学生答案、作答无法识别的评分点按0分计入失分并记录原因；材料缺失或判题依据不足才待核。当前网页按低置信度自动待核的逻辑须相应调整，不能只修改提示词。
2. 先建立题号清单，再按清单核对批改覆盖，包括小问和跨页归属。页数读齐不能当作题目齐全。首版整卷校验通过才定稿；后续按已确定的题组持久化结果时，必须显示暂定分与缺项。
3. 阶段 A 结果原子落盘，固定 `gradeSetId` 后立刻排评分 PDF。阶段 B 自动接续，用户先看到“评分卷可下载，详细解析生成中”。两个阶段各自成功、待核、失败及重试。
4. `api/grading-runs.js` 的执行记录按阶段隔离；每个阶段提交前保存稳定 taskId、输入哈希与源版本。观察断线先 attach 原任务；只在确认可续接时按现有机制 resume，绝不自动重批已完成评分。
5. 已保存的 v1 任务继续可读、可下载；新增版本适配层供旧渲染器读显示字段，保留原结果。旧结果不能凭空补出评分证据或精细坐标。

### P1：定位与 PDF 质量

1. 统一保存原页坐标、题目/作答矩形与手写行段；可选 OCR 提供候选位置，由视觉核对，不把 OCR 当答案真值。合成答题纸分栏阅读，保存到原页的变换。
2. 定位与评分置信度分开；低定位置信度保留边栏提示，不把正确答案判断一起降为错题。密集区域用引线和分页放大，避免为放满卡片反复缩小原卷。
3. PDF 原页/原图作为底层，勾叉、分数和引线作为矢量覆盖；方向变换仅作用于位置，标签以最终阅读方向绘制。原生 PDF 尽量直接保留页面，扫描图片避免重复 JPEG 压缩。
4. 已实现：解答默认离线HTML，可搜索、复制，含数学公式、化学方程式与知识总结，按需打印PDF。后续完善精确原题裁片、作文/主观题行级红绿线；无需AI回传整张重绘试卷。
5. 渲染器保留跨平台部署：优先项目本地提供的 JS PDF/字体与公式资源，按实际打包和性能结果选库；不把用户安装 Python/TeX 作为应用运行前提。聊天生成可使用当前可用 PDF 工具。

### P2：复用与可核验的提速

- 缓存键包含文件哈希、页/裁片、方向、处理器及技能版本。更正一个作答只重批相关题及其共用材料依赖；新评分版本使对应解析过期，旧版保留。
- 导出缓存分开依赖：评分 PDF 绑定评分＋标注＋渲染版本；解答 PDF 还绑定解析与技能版本。只改位置或排版不再调用模型。
- 指标记录为本地匿名耗时：预处理、评分完成、HTML 批改卷可查看、解析完成、重连取回时间及失败原因；分开比较相同卷量与附件质量，不承诺未实测的固定秒数。

## 技能如何进入应用

- 项目聊天：按 `AGENTS.md` 读取 `skills/exam-grading/SKILL.md` → `skills/exam-analysis/SKILL.md`；英语加学科细则。
- 网页 Tandix 任务目前没有技能工具，保存目录不会自动生效。待实现本机服务端按固定技能白名单读取规则，编译对应阶段提示并记录内容哈希；不接受模型指定任意文件路径。按阶段只加载必需规则与材料。
- 评分和解析通过[交接约定](../skills/exam-grading/references/handoff.md)共用证据，原批、新参考分和正式分始终分开；解析发现冲突输出复核项，不能反向静默改成绩。
- 网络恢复沿用原任务取回机制。Tandix 本机执行器完全断网时是否仍继续取决于执行环境，不能把持久任务恢复宣传成保证云端不停算。

## 验收标准

1. 解析仍在执行或失败时，已完成的评分 PDF 可独立下载；导出失败不重跑模型。
2. 题号清单全覆盖；跨页/小问不重计；rubric、题型及总分一致。缺分值可显示明确标注的 8/10 参考分。完整答卷中未作答或无法识别的评分点记0分且不阻塞出卷；只扣对应评分点，保留可确认的正确步骤分；材料缺失不能判成学生答错。
3. 每个新增勾叉和分数能对应真实作答；0/90/180/270°下位置正确、标签正向、无内容遮挡，原件保留。
4. 重连、刷新、提交确认丢失和任一阶段恢复均不会重复新建已完成任务，且可取回已保存的结果。
5. 评分PDF与解答HTML（或按需PDF）使用同一评分快照；改分后旧版标为过期。解答包含完整题目/选项、原图、主观题红绿批注及本卷知识技巧。
6. 用虚构试卷检查 Mac、Linux、Windows 的安装、中文字体、PDF 导出和内存；真实手写准确率另设经授权样本验收，不用模拟协议测试代替。


## 2026-10-22：HTML 主流程与独立题图评估（已实施）

结论：可行，采用结构化题目 + 独立图片 + HTML 展示。PDF 是按需导出，不再充当错题采集的数据源。HTML 本身不代替数据存储，也不能自动纠正旧题缺图。

- 输入保留图片/PDF；原件不覆盖。AI 返回已有逐题 JSON 与精确题图区域，所有题目都整理，含正确题。
- 评分落盘后，本机生成独立 JPEG；清单按评分版本保存题目 ID、SHA256、来源页、矩形、方向、角色、完整性。失败只影响图片，不回滚已保存评分。
- 在线批改/解答 HTML 引用文件 URL，显示逐题按钮。点击只提交任务 ID、题目 ID 和评分版本，服务端复用数据与图像，无需填写、截图或上传；重复提交幂等。
- 错题本保留图像副本，源卷删除不破坏已有错题和组卷；新成绩与旧报告发生冲突时拒绝收录并要求刷新。
- 离线下载 HTML 嵌入图片/字体，确保可移交和断网阅读；在线版负责收录交互。二者内容来自同一评分快照。
- 批改和解答都通过 HTML 打印为 PDF；打印展开内容、等待字体与图像，已有 PDF 保留下载，不再自动重排 PDF。
- 有逐题 JSON 的旧任务打开即可迁移生成题图/HTML，不调用模型、不重评分。只有 PDF、没有结构化结果的历史材料仍需一次识别；缺精确题框仅作核对截图，后续自动补齐清洁题面。

验收重点：独立图片在收录前存在；跨页题的多张图映射正确；点击报告按钮保存正确图片与原解答；旧版本拒绝、重复点击不重复；可打印题面不混入学生答案；离线/打印可读，来源删除不丢错题。真实模型识别准确率与本次格式迁移分开验证。
